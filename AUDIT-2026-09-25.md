# Koers audit — 25 September 2026

Status: verified defects corrected; production build verified. Publication is tracked in the [GitHub Pages deployment workflow](https://github.com/freddywinkel/koers-app/actions/workflows/deploy.yml).

## Scope and baseline

Reviewed startup and routing, PIN gating, IndexedDB schema and upgrades, import/export/deletion, draft recovery, settings, lesson and exercise flows, check-ins, safety plans, translation boundaries, reminders, audio, service-worker updates, dependencies, CI, and production assets. Three independent reviews covered storage, user flows, and release/PWA behavior, followed by integration review and browser checks.

The checkout started at `d9a4b9f` on `main`, with no tracked changes. Existing PDFs, `Theme switching/`, `design/`, and `taal-audit-2026-07-20/` were preserved. Browser mutations used synthetic records at the audit-only local origin `127.0.0.1:42863`; existing profiles on other origins were left untouched.

Existing tests passing was treated as a baseline, not evidence that failure paths were safe. The dependency scan initially reported six affected build/development packages: four high and two moderate. The installed dependency directory also contained inconsistent npm/pnpm remnants.

## Corrected findings

| Priority | Finding and consequence | Correction and evidence |
| --- | --- | --- |
| P1 | Clear-all used separate transactions, allowing partially deleted data after a failure. | All tables now clear in one transaction. Failure injection verifies complete rollback and preservation of recovery data and PIN state. |
| P1 | Safety-plan editor identity could diverge from the record being displayed; a late save could write old text into a new plan. | Writes are bound to each editor's record ID. New-plan creation waits for pending writes. Browser verification confirms the old plan retains its text and the new plan starts empty. |
| P1 | Autosave marked fields clean before successful persistence and could lose changes after write failures. | Serialized writes retain unsaved revisions, show errors, and allow retry without retyping. Tests cover failures, overlapping writes, and edits made during a slow save. |
| P2 | Export read each table independently, so concurrent edits could produce an inconsistent backup. | One read transaction captures a coherent snapshot, with a test that writes concurrently. The latest recovery draft is included. |
| P2 | Legacy safety-plan exports restored source rows but did not create a visible current-format plan. | Shared migration logic handles both database upgrades and older exports. Tests verify exact text preservation and no duplicate migration. |
| P2 | Replace import could leave an older recovery draft able to reappear. | Recovery cache follows the successfully committed import. Failed replacement rolls back records and leaves the original recovery cache intact. |
| P2 | Several imported dates and IDs could be finite numbers but invalid JavaScript dates or unsafe integers. | All relevant timestamps and auto IDs are validated before mutation, including the export date used for migration. |
| P2 | Early typing during G-schema draft loading could discard previously saved fields. | Restore merges untouched stored answers with new edits; explicit cleared answers and zero percentages are preserved. Recovery remains available if IndexedDB reads fail. |
| P2 | Profile name could miss asynchronous settings hydration. Failed settings writes could already change the startup cache. | Controlled name input loads saved values; startup cache changes only after a successful database write. Save, export, and deletion failures are visible. |
| P2 | Language-changing imports/reset could leave the UI runtime inconsistent with settings. Blocked cache writes could hide the canonical language. | Imports return committed language atomically; successful changes reload the runtime. Startup reads the database preference, with an in-memory language when localStorage is unavailable. |
| P2 | A session unlocked for one PIN also unlocked a subsequently changed PIN. | P2 | Language initialization failure occurred before the React error boundary existed, leaving an empty screen. | Startup failures now render the existing recovery screen. |
| P2 | Consecutive lessons reused a heading node and left page title/focus/announcements on the old route. | Route content is keyed by pathname. Browser checks verified consecutive lesson titles and keyboard focus, including offline navigation. |
| P2 | Translation could rewrite displayed user notes/names/answers and protected accessibility attributes. | User-owned text and protected attributes are excluded. The modal could be dismissed while activation continued. | Bounded activation with cleanup, retry feedback, offline activation, disabled dismissal during activation, and a backdrop preventing background editing. |

## Verification

- `npm run build:pages`: typecheck, **93 product tests** (26 JavaScript + 67 TypeScript), production Pages build, and **8 artifact tests** passed: **101 total**.
- After the last wording-only correction, typecheck, all three language tests, Pages build, and all eight artifact tests were rerun successfully.
- `npm audit`: zero known vulnerabilities. `npm audit --omit=dev`: zero known vulnerabilities. Clean installation resolves the declared dependency tree.
- `git diff --check`: passed. A filename-only scan of tracked files for common private-key/token patterns produced no matches; this is not a comprehensive secret-scanning guarantee.
- Existing 51 core lesson IDs, 24 theory lessons, 25 illustration assets, and Dutch/English guided-audio integrity checks remain passing.
- Manifest identity `./`, start URL `./#/check-in`, scope `./`, and Pages base `/koers-app/` are preserved. The generated service worker precaches 83 entries.

Browser checks in the Codex Chromium browser:

1. Fresh onboarding and sequential completion through the check-in unlock.
2. Automatic popup saves and closes; manual check-in saves and returns to Today. Two same-day entries retain their own times, newest first.
3. Profile name persists across reload and language switch. English UI leaves user-entered `Vandaag` unchanged.
4. Typing into a safety plan and then creating a new plan preserves the previous answer only in the previous plan.
5. A G-schema draft survives immediate navigation away and back.
6. An update is discovered and activated through the normal prompt. With the preview server stopped and origin connectivity confirmed unavailable, the already downloaded update activates and the app reloads successfully. Check-ins remain intact.
7. Previously downloaded English audio plays offline; its displayed playback time advances to 0:13 and pauses successfully. This confirms playback behavior, not a subjective assessment of sound quality.
8. Consecutive lesson routes update document title and heading focus while offline.
9. Rendered layouts inspected at 390×844, 320×568, and 1024×768. The narrow viewport reports document width 320 with no horizontal overflow.

During an intentional local build replacement, an already open preview requested a superseded lazy chunk. The recovery screen appeared, reload recovered, and the normal update flow subsequently worked. This interrupted-preview condition was distinguished from stable-build failures.

## Boundaries and remaining device verification

- This report records the audit and pre-publication checks. Public release status is tracked separately in the deployment workflow linked above.
- Physical iPhone/iPad installation, Safari audio behavior, OS notification delivery, and device-specific update/lifecycle handling still require device checks. Desktop browser evidence does not establish those outcomes.
- Abrupt OS termination can prevent a final IndexedDB autosave from completing. Normal navigation, retry, transaction failure, and the existing G-schema recovery journal were checked; guaranteed survival of every force-close was not claimed.
- Notifications still depend on the app being open, as the UI explains. Web Locks prevents simultaneous-tab duplication where that browser feature is available.
- This was an engineering and sampled content/translation audit, not clinical validation or a professional review of every lesson. No treatment protocol or dosing guidance was added.
